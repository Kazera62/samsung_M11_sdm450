# NOCTURNE // SDM450
### SAMSUNG KERNEL PROJECT

**ENGINEERED FOR CONTROL. BUILT FOR PERFORMANCE.**

NOCTURNE is an independent kernel development project for Samsung devices based on the Qualcomm Snapdragon 450 platform. This repository contains the kernel source and device-specific configuration used for development, testing, and performance work.

> Source first. Deliberate changes. No unnecessary baggage.

## Build

The automated workflow is **[BUILD-NOCTURNE](.github/workflows/BUILD-NOCTURNE.yml)**.

1. Open the repository's **Actions** tab.
2. Select **NOCTURNE // SDM450 Kernel Build**.
3. Click **Run workflow** on the branch you want to build.
4. When the job finishes, open the run and download its artifact.

The build configuration is intentionally fixed to one defconfig and one root integration route to keep testing consistent.

| Setting | Configuration |
|---|---|
| Defconfig | `a11q_open_defconfig` |
| Compiler | LineageOS Clang r416183b toolchain |
| Cross-compilers | AArch64 and ARM32 GCC 4.9 |
| Root integration | ReSukiSU-compatible upstream integration |
| SUSFS | Enabled |
| Packaging | AnyKernel3 ZIP generated by the upstream build framework |

## ReSukiSU and SUSFS

NOCTURNE uses the integration flow provided by [NonGKI_Kernel_Build_2nd](https://github.com/JackA1ltman/NonGKI_Kernel_Build_2nd), rather than keeping root-integration code in this source tree.

The upstream template currently exposes its SUSFS-capable automatic integration through `KERNELSU_AUTO_GET=true` and `KERNELSU_AUTO_FORK=bakasu`. The workflow keeps this configuration enabled and applies the upstream framework's generic Linux 4.9 SUSFS patch.

No device-specific fixed SUSFS patch for this M11/SDM450 source is configured yet. Patch diagnostics are enabled; if the generic patch cannot be applied cleanly, the workflow is intended to stop and expose the rejected patches rather than silently treating an incomplete integration as a successful build. That situation will require a source-compatible patch or adjustment.

### Upstream updates

Each run checks out the latest `mainline` branch of the upstream build framework and obtains its root integration through the configured upstream installer. Updates merged into that framework are therefore used by the next build without copying its code into this repository.

The workflow is manually triggered: an upstream update does not itself start a new build.

## Build output

The upstream framework packages the compiled kernel into an AnyKernel3 ZIP and uploads the output as a GitHub Actions artifact. AnyKernel3 is fetched by the framework into the temporary runner workspace; its installer files are **not committed to this kernel source repository**.

The artifact can contain the flashable ZIP and any additional diagnostic files uploaded by the upstream build steps. A completed build is not, by itself, proof of device compatibility or runtime stability.

## Development principles

- **Clean source:** root integration and packaging tools stay outside the tracked kernel source by default.
- **Consistent configuration:** one defconfig is used for repeatable test runs.
- **Traceable builds:** the selected source branch and upstream build framework define each run's inputs.
- **Evidence-based tuning:** report performance changes only after verifying them on the target hardware.

## Disclaimer

Custom kernels can cause boot loops, instability, thermal issues, data loss, or device malfunction. Confirm the target model, keep a known-good boot image and a recovery method available, and test before daily use. No universal compatibility or stability guarantee is provided.
